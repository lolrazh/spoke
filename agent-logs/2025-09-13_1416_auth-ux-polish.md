# Tasteful Auth UX & Pill State Orchestration

**Date:** 2025-09-13  
**Agent:** OpenAI Coding Agent (Codex CLI)  
**Status:** ✅ Completed  

## User Intention
The user wanted a patient, tasteful experience around authentication transitions, not just a one-off notification. Specifically, they aimed to centralize sign-in/out state management, eliminate abrupt window hides, and remove the delay when the pill appears after signing in. The deeper goal is a consistent, high-polish UX where the pill gracefully communicates state (notifications) and fades in/out without jank.

## What We Accomplished
- ✅ **Centralized auth transitions in renderer (App.tsx)** – Single conductor for SIGNED_IN/SIGNED_OUT; removed duplicate, competing window operations.
- ✅ **Tasteful sign-out sequence** – Show “Signed out” notification → settle to resting → smooth fade-out → onboarding fades in.
- ✅ **Tasteful sign-in sequence** – Ensure pill shows with a fade and display “You’ve been signed in.” (renderer-only, no duplicates).
- ✅ **Added smooth fades in main process** – Implemented `smoothHide()` to complement `smoothShow()` so window hides are not abrupt.
- ✅ **SettingsPanel defers to App.tsx** – Sign-out no longer directly hides the pill or opens onboarding; prevents race conditions.
- ✅ **Pre-created pill during onboarding** – `preparePill()` is called early so the pill is ready to show instantly after sign-in.
- ✅ **Moved profile ensure off the critical path** – UI shows immediately after sign-in (when permissions allow); `ensureProfileRow()` runs in the background.
- ✅ **Removed duplicate sign-in notification** – Main-process notify after onboarding complete was removed; renderer is the single source for the toast.

## Technical Implementation
- Renderer (App.tsx) owns auth UX transitions via Supabase `onAuthStateChange`:
  - On SIGNED_IN: call `showFloatingBar()` (now faded) and `notifications.send("You’ve been signed in.")`.
  - On SIGNED_OUT: cancel capture; show `notifications.send("Signed out")`; then a post-notification hook triggers `floating-bar:hide-indefinitely` (fade-out) and finally opens onboarding.
- Post-notification handoff: extended `pendingHideAfterCollapse` to include an `onAfter` callback, invoked after the fade completes for clean transitions.
- Main (main.ts): added `smoothHide(win, fadeMs)`; replaced `hide()` calls in hide flows; onboarding show now fades in; show flow already used `smoothShow`.
- Onboarding (Onboarding.tsx): pre-creates pill early with `preparePill()`. After successful auth, if permissions are granted, immediately `onboardingComplete()` and show the pill; kick off `ensureProfileRow()` in the background. If not, proceed to permissions and still background the ensure.

**Files Modified:**
- `src/components/App.tsx` – Centralized sign-in/out flow; notification→fade→onboarding handoff; minor delays to sync with fades.
- `src/components/SettingsPanel.tsx` – Sign-out collapses first and defers orchestration to App.tsx; removed direct hide/show.
- `src/main.ts` – Added `smoothHide()` and used it for all hides; onboarding fades in; `floating-bar:show` uses `smoothShow`.
- `src/components/Onboarding.tsx` – Pre-create pill early; background `ensureProfileRow()`; avoid blocking UI on profile fetch.

## Bugs & Issues Encountered
1. **Abrupt pill disappearance on sign-out** – SettingsPanel directly hid the window and opened onboarding, racing with App.tsx.
   - **Fix:** Centralized flow in App.tsx; added smooth fade-out in main; SettingsPanel no longer manipulates window visibility.
2. **Pill appears with a delay after sign-in** – Window wasn’t created until late in onboarding; DB calls (profile ensure/fetch) blocked UI.
   - **Fix:** Pre-create pill window with `preparePill()` during onboarding; perform `ensureProfileRow()` in the background.
3. **Duplicate sign-in notifications** – Both main and renderer emitted toasts.
   - **Fix:** Removed main-process notify; renderer is the single source of truth for notifications.

## Key Learnings
- **Renderer should own UX orchestration** for auth; main should focus on window mechanics (fade/position) to avoid races.
- **Pre-warming windows** (creating off-screen) eliminates perceived lag and is especially valuable for high-polish surfaces like the pill.
- **Backgrounding non-UI-critical IO** (e.g., profile ensure/fetch) keeps the interface responsive and predictable.

## Architecture Decisions
- **Single conductor for auth transitions (App.tsx)** – Reduces jank from competing sources (SettingsPanel/main).
- **Fade both ways** – `smoothShow` + `smoothHide` make visibility changes feel intentional, not abrupt.
- **Background DB operations** – UI first; server-side state is synchronized without blocking.
