## Key Learnings

### Performance Insights

- **Worker routing overhead is negligible**: Regex matching, string operations, and provider selection add ~0.5ms total, representing <1% of end-to-end latency
- **Real bottleneck is provider APIs**: Network RTT + model processing accounts for 500-2000ms, dwarfing code execution time
- **Workers free plan CPU limit (10ms) is ample**: Current routing logic uses ~1ms, leaving 9ms headroom before needing paid plan
- **Paid Workers plan won't improve routing speed**: Upgrading CPU from 10ms→50ms irrelevant when code uses <1ms

### AI Gateway Caching Behavior

- **Cache key composition**: Endpoint + model + messages + parameters (temperature, top_p, etc.)
- **Single character difference = cache miss**: Even minor prompt variations prevent hits
- **Edit mode has higher hit potential**: Common instructions ("make shorter", "fix grammar") repeat more than unique dictation
- **Dashboard-only caching limits**: No per-request TTL control, no mode-specific strategies, limited observability
- **Conservative projections**: 10-15% improvement for dictation, 25-40% for edit mode (assuming dashboard defaults work reasonably)

### Cloudflare Gateway Architecture

- **Not all providers behind gateway**: OpenAI and OpenRouter currently bypass gateway (direct connections), only Groq, Baseten, and now Cerebras use it
- **Gateway adds ~10-20ms overhead**: Small fixed cost for routing through Cloudflare edge, offset by caching benefits
- **Cache TTL control via headers**: `cf-aig-cache-ttl` header enables per-request control (not yet implemented)
- **Cache status observable**: Response includes `cf-cache-status` header (HIT/MISS/EXPIRED) for monitoring

## Architecture Decisions

### Why Not Implement Code-Level Caching Yet

**Decision:** Document caching strategy but defer implementation until dashboard testing completes

**Rationale:**
- User already enabled caching via dashboard (zero-code approach)
- Need baseline metrics to validate 10-40% improvement projections
- Code-level headers add complexity without proven need yet
- Dashboard approach lets us test cache hit rates before committing to TTL values

**Trade-off:** Less granular control (no per-mode TTLs, uniform settings) but faster validation of caching value

### Why Cerebras as Default Provider

**Implied decision:** User set Cerebras as new default for both dictation and edit

**Advantages:**
- Fast inference (50-150ms TTFB, competitive with Groq)
- Good model quality (llama-3.3-70b, qwen-3-235b)
- Already behind AI Gateway (caching enabled)
- Cost-effective for volume use

**Context:** Replaces Baseten as default, likely for speed or cost reasons

### Provider Routing Strategy

**Pattern:** Centralized router (`chatCompleteByProvider`) with provider-specific implementations

**Why this works:**
- Single responsibility: each provider file handles only its API quirks
- Easy to add providers (this session proved it - 6 files modified)
- Consistent instrumentation (Sentry spans in every provider)
- Runtime provider switching via env vars or routing rules
