# PTT Hands-Free Reliability

**Date:** 2025-10-15  
**Agent:** GPT-5 Codex  
**Status:** ✅ Completed  

## User Intention
The user wanted to harden the hands-free (double-tap) gesture so that customers no longer experience missed toggles. Beyond merely suspecting user timing, they sought root-cause analysis of potential race conditions and a concrete fix that restores reliable detection.

## What We Accomplished
- ✅ **Diagnosed gesture race** – Confirmed the 25 ms trailing debounce on hotkey callbacks left `isOptionDown` stuck, preventing the second tap from registering as a double.
- ✅ **Stabilized double-tap flow** – Replaced the debounce with a leading-edge throttle and widened the hold/double windows (100 ms / 300 ms) to better match real cadence while preserving guards.

## Technical Implementation
Swapped the renderer’s hotkey subscription to a leading-edge throttle so the first event fires immediately while subsequent chatter is suppressed, eliminating double-dispatch while keeping the state machine in sync with real taps. Adjusted hold and double-tap thresholds to provide more tolerance without impacting long-press semantics.

**Files Modified:**
- `src/components/App.tsx` – Added `leadingThrottle`, applied it to `window.ptt` handlers, and bumped gesture timing constants.

## Bugs & Issues Encountered
1. **Double-tap misses due to trailing debounce** – The 25 ms debounce queued the key-up/down handlers, leaving `isOptionDown` true during the second tap so the double-tap branch never ran.  
   - **Fix:** Remove the trailing debounce, replace it with a leading-edge throttle, and reset timers immediately on key-up.

## Key Learnings
- **Modifier state must clear synchronously** – Even tiny delays on synthetic hotkey listeners can corrupt gesture state machines.
- **Human cadence tolerance matters** – Slightly wider timing windows drastically reduce perceived flakiness without hurting responsiveness.
- **Trace HUD is valuable** – The in-app trace logging remains crucial for validating gesture flows during manual QA.

## Architecture Decisions
- **Keep logic in renderer** – Addressed the race within the React handler rather than touching the native helper, maintaining existing IPC boundaries.
- **Leading throttle over debounce** – Chose a throttle so we fire immediately but rate-limit duplicates, preserving responsiveness while filtering helper chatter.

## Ready for Next Session

- 🔧 **Long-term QA** – Consider automating hotkey timing tests or capturing anonymized timing metrics if users report edge cases.

Hands-free toggling now aligns with real-world tapping speed, reducing support friction. Future work can build on this by adding automated gesture tests or additional telemetry without revisiting the native helper layer.
