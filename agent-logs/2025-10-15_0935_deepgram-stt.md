# Deepgram STT Integration

**Date:** 2025-10-15  
**Agent:** Codex (GPT-5)  
**Status:** ✅ Completed  

## User Intention
The user wanted the worker transcription service to support Deepgram as a selectable STT provider, configured via the runtime config instead of environment files, and to align the implementation with existing provider patterns. After initial integration, they further requested stripping non-essential Deepgram query parameters so the API call remains raw and minimal.

## What We Accomplished
- ✅ **Added Deepgram STT provider** - Implemented `providers/deepgram.ts`, wired dispatcher/config/runtime updates, and exposed provider selection via `STT_PROVIDER`.
- ✅ **Expanded test + doc coverage** - Added unit tests for routing/Deepgram requests and refreshed `docs/TRANSCRIPTION.md` with provider/env guidance.
- ✅ **Simplified Deepgram request** - Removed default `punctuate/paragraphs` params and updated dispatcher/tests/docs to reflect the lean API call.

## Technical Implementation
Deepgram now mirrors the Groq/Fireworks provider shape: the dispatcher picks defaults via `defaultModelFor`, Sentry spans capture request/response timing, and `wrapWav` output feeds directly into the minimal `/listen` POST. Runtime config now maps provider → default model without relying on `.dev.vars`.

**Files Modified:**
- `worker/src/config.ts` - Added Deepgram endpoint/model constants and set provider defaults.
- `worker/src/config/runtime.ts` / `.test.ts` - Provider parsing + default model logic extended to Deepgram.
- `worker/src/services/stt/providers/deepgram.ts` - New implementation using raw fetch and slim query params.
- `worker/src/services/stt/index.ts` / `.test.ts` - Dispatcher now routes Deepgram and tests assert provider-dependent defaults.
- `worker/src/services/stt/deepgram.test.ts` - Ensures request formatting/error handling without optional params.
- `worker/src/handlers/ws.ts` - Selects Deepgram API key/endpoint when runtime provider flips.
- `docs/TRANSCRIPTION.md` - Documented provider behavior and env bindings.

## Bugs & Issues Encountered
1. **Default-provider test failure** - After switching the repo’s `STT_DEFAULT_PROVIDER` to Deepgram, the dispatcher test still assumed Groq.
   - **Fix:** Generalized the assertion to respect the configured default provider, preventing brittle expectations.
2. **Optional query parameters persisted** - Initial Deepgram implementation appended `punctuate`/`paragraphs`, conflicting with the user’s request.
   - **Fix:** Removed those flags from both provider options and documentation, ensuring the API call is raw.

## Key Learnings
- **Runtime defaults matter for tests** - Unit tests relying on `STT_DEFAULT_PROVIDER` must reference the exported value rather than hard-coded expectations.
- **Deepgram accepts raw WAV bodies** - No multipart/form-data needed; direct `audio/wav` payload keeps the worker implementation lighter.
- **Sentry spans remain reusable** - The existing instrumentation pattern works seamlessly for new providers with minimal attribute tweaks.

## Architecture Decisions
- **Use minimal query parameters** - Chose to rely on Deepgram’s defaults to match user intent and reduce maintenance overhead.
- **Provider-specific defaults centralized** - Extended `defaultModelFor` to keep model selection consistent across providers without env-variable sprawl.
