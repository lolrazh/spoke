# VAD Gating and No‑Speech Suppression

**Date:** 2025-10-06  
**Agent:** Droid  
**Status:** ✅ Completed  

## User Intention
The user wants voice activity detection re‑enabled correctly to prevent trailing‑silence hallucinations (e.g., “Thank you so much”) and ensure that if a user opens dictation but never speaks, no transcription request is sent. They explicitly do not want VAD to close the session or auto‑finalize; session lifecycle remains under client control (hotkey release). The goal is a cleaner UX via gating, not altering the protocol semantics.

## What We Accomplished
- ✅ **Re‑enabled gate‑only VAD** — Turned on the existing Silero/ORT VAD layer and kept policy strictly as a network gate (no auto‑finalization).
- ✅ **No‑speech request gating** — If VAD forwards zero frames, the client skips `{ type: "end" }` and sends `{ type: "cancel" }` (no socket close) so the worker releases the logical session while we continue reusing the same WebSocket.
- ✅ **Start behavior aligned with VAD** — Disabled the unconditional 300ms initial bypass when VAD is enabled; rely on pre‑roll + speech_start flush to avoid start clipping while not sending silence.
- ✅ **Assets/deps verified** — Confirmed `public/vad/*` assets and Vite static‑copy rules; dependencies `@ricky0123/vad-web` and `onnxruntime-web` present.
- ⚠️ **Manual validation pending** — Recommend testing quick bursts, trailing silence, and no‑speech cases with dev logs on; thresholds can be tuned as needed.

## Technical Implementation
- Gate is implemented via `VadStreamGate` slicing 16k Int16 frames into 30ms Float32 windows, applying hysteresis (`VadGate`), keeping a pre‑roll ring, and forwarding full input frames only while speaking plus a brief tail.
- In `useTranscription.ts`, when VAD is enabled, the initial bypass is set to 0 so silence isn’t unconditionally streamed. We track `framesForwarded`; if zero at stop, we suppress `{ type: "end" }`, send `{ type: "cancel" }` (or queue on open), and resolve without closing the socket.

**Files Modified:**
- `src/config/vad.ts` — `VAD_ENABLED = true` (gate‑only mode remains).
- `src/hooks/useTranscription.ts` —
  - Disable 300ms bypass when VAD is enabled; rely on pre‑roll + gate.
  - Add gating at stop(): if `framesForwarded <= 0`, skip sending `end`, send a `cancel` control message, and do local audio teardown; keep the socket open for reuse.

## Bugs & Issues Encountered
1. **Worker session stuck when no end/cancel** — Skipping both `end` and `cancel` left `sessionActive` on the worker, causing it to ignore the next `start` on the same socket.
   - **Fix:** Send `{ type: "cancel" }` on the no‑speech path (do not close the socket) to release the logical session while preserving connection reuse.
2. **Start clipping vs. silence forwarding** — The unconditional 300ms initial passthrough could send silence or misalign with VAD warmup.
   - **Fix:** When VAD is enabled, rely on pre‑roll and `speech_start` flush; keep unconditional bypass only when VAD is disabled.

## Key Learnings
- **VAD should not own lifecycle** — In gate‑only designs, VAD decides what audio is forwarded but must not send control messages or close sockets.
- **Simple metric gating works well** — `framesForwarded` is an effective, low‑overhead signal to suppress requests when there was no speech.
- **Asset resolution matters** — Silero/ORT assets are correctly served via Vite static‑copy and `BASE_URL`‑aware URL builders; this avoids file:// path issues in packaged apps.

## Architecture Decisions
- **Gate‑only VAD, no auto‑finalize** — Preserve the existing WS protocol and let the user action (hotkey release) drive session end.
- **Bypass off with VAD on** — Avoid unconditional pre‑speech streaming; rely on pre‑roll flush to retain leading syllables.
- **Request suppression with session release** — On no‑speech, don’t send `end` but do send `cancel` so the worker releases the session; keep WS connection for reuse.
