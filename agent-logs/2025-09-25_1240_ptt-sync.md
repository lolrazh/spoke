# Option Gesture Synchronization

**Date:** 2025-09-18  
**Agent:** Codex (GPT-5)  
**Status:** ✅ Completed  

## User Intention
Improve the Option-key push-to-talk experience so that onboarding hotkey drills do not silently start dictation and a single tap can never leave the microphone running in the background. The underlying goal was to move toward a single orchestration path that keeps pill visuals and audio capture strictly in sync.

## What We Accomplished
- ✅ **Scoped gesture controller in pill renderer** - Introduced gesture tokens and Option-key state tracking so long-press, double-tap, and click paths only start the mic after the same controller confirms permission and key state.
- ✅ **Hardened onboarding isolation** - Ensured onboarding hotkey pages keep `pttTarget` on the onboarding window, preventing mirrored Option events from hitting the pill while it is hidden.
- ✅ **Hands-free double-tap guardrails** - Added tokenized double-tap gating so duplicate `ptt-up` emissions or stale timers can’t misclassify a single press as hands-free start.

## Technical Implementation
Centralized all PTT gesture transitions inside `src/components/App.tsx` with a token-based pipeline that gates microphone starts behind permission checks and current key state. Refined the onboarding helper routing (`src/components/Onboarding.tsx`) to leave `pttTarget` on `"onboarding"` until the pill is actually revealed. Updated the main-process helper relay (`src/main.ts`) so Option/Command events are mirrored to the other window only when the pill is the active recipient.

**Files Modified:**
- `src/components/App.tsx` - Added gesture token controller, delayed mic start until token validation, synchronized UI/mic stop semantics.
- `src/components/Onboarding.tsx` - Held `pttTarget` on onboarding during hotkey-info step to avoid background dictation starts.
- `src/main.ts` - Stopped mirroring Option/Command events to the pill window while onboarding owns PTT.

## Bugs & Issues Encountered
1. **Hidden pill activating dictation during onboarding** - Option taps on the onboarding tester triggered the pill via mirrored helper events even though it was cloaked.  
   - **Fix:** Keep `pttTarget` on onboarding and gate main-window mirroring unless the pill is the designated target.
2. **Single tap launching hands-free in the background** - Rapid duplicate `ptt-up` events reused the last tap timestamp and went straight into the double-tap branch, calling `start()` without verifying key state.  
   - **Fix:** Track `isOptionDown`, reset timers on stray ups, and require a valid token before double-tap activation can reach the transcription hook.

## Key Learnings
- **Helper mirroring needs explicit routing guards** - Sharing modifier events between windows without checking `pttTarget` leaks gestures into hidden UI.
- **Async permission gates demand idempotent tokens** - Without a token/nonce system, callback lag can race against key-up events and start the mic after the gesture finished.
- **Hands-free toggles must own their timers** - A persistent timestamp cache is not sufficient; every entry must be tied to a currently-active keypress to avoid phantom toggles.

## Architecture Decisions
- **Tokenized gesture orchestration** - Chosen to avoid invasive native changes while guaranteeing that only one code path triggers `trans.start()`. Alternatives (main-process FSM) were heavier and risked onboarding regressions.
- **Renderer-led gating** - Kept gating in the renderer to reuse existing permission checks and avoid duplicating auth/mic logic in native code, accepting a slight debounce cost for consistency.
